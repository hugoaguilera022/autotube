# AutoTube — YouTube Automation setup (La Última Clave)

## What is already implemented

- Persistent Supabase schema for channels, stories, jobs, publications and analytics snapshots.
- La Última Clave channel configuration.
- YouTube OAuth now requests upload + account + Analytics read permissions.
- Server endpoint to upload an MP4 and optionally schedule it with `publishAt`.
- Optional thumbnail upload.
- Optional playlist insertion.
- YouTube Analytics report endpoint.
- Automation config endpoint.

## Required manual setup

### 1. Supabase

Run this file in the Supabase SQL Editor:

`supabase/migrations/20260930_youtube_automation.sql`

Do not skip this step. The application will not create these tables automatically.

### 2. Google Cloud

In the same Google Cloud project used by AutoTube:

1. Enable **YouTube Data API v3**.
2. Enable **YouTube Analytics API**.
3. Confirm the OAuth consent screen is configured.
4. Keep the authorized redirect URI exactly equal to the Render callback:
   `https://YOUR-RENDER-DOMAIN/api/youtube/callback`

AutoTube requests these scopes:

- `youtube`
- `youtube.upload`
- `youtube.readonly`
- `yt-analytics.readonly`

### 3. Render environment variables

Keep/set:

- `YOUTUBE_CLIENT_ID`
- `YOUTUBE_CLIENT_SECRET`
- `YOUTUBE_REDIRECT_URI=https://YOUR-RENDER-DOMAIN/api/youtube/callback`
- `APP_URL=https://YOUR-RENDER-DOMAIN`
- `SUPABASE_URL`
- `SUPABASE_SECRET_KEY` (or existing `SUPABASE_SERVICE_ROLE_KEY`)
- `YOUTUBE_TOKEN_ENCRYPTION_KEY`

Do not put these secrets in GitHub.

### 4. Deploy

Push/merge the commits from this implementation to Render and wait for a successful deploy.

### 5. Re-authorize YouTube

This is mandatory after the scope change.

Open:

`https://YOUR-RENDER-DOMAIN/api/youtube/auth`

Approve the new permissions. This replaces the old read-only authorization with the upload + Analytics permissions.

### 6. Verify connection

Open:

`https://YOUR-RENDER-DOMAIN/api/youtube/profile`

Expected:

`{"connected":true,...}`

### 7. Verify automation configuration

Open:

`https://YOUR-RENDER-DOMAIN/api/youtube/automation-config`

It should return the La Última Clave configuration.

### 8. First upload test

Do NOT enable daily automation yet.

Use a known-good MP4 generated by AutoTube and call:

POST `/api/youtube/upload`

JSON body:

```json
{
  "filePath": "/absolute/path/to/video.mp4",
  "title": "La Última Clave — Prueba",
  "description": "Vídeo de prueba del sistema de automatización.",
  "visibility": "private",
  "tags": ["misterio", "suspense", "historias"],
  "categoryId": "24"
}
```

The response should contain `videoId`.

### 9. First scheduled-publication test

After the private upload works, schedule a test:

```json
{
  "filePath": "/absolute/path/to/video.mp4",
  "title": "La Última Clave — Prueba programada",
  "description": "Prueba de publicación programada.",
  "publishAt": "2026-10-01T18:00:00Z",
  "visibility": "private"
}
```

Keep the first test private/unlisted until the complete pipeline is verified.

### 10. Analytics test

Open:

`/api/youtube/analytics?start=2026-09-01&end=2026-10-01`

The endpoint should return `columnHeaders` and `rows`.

## Important YouTube restriction

Google states that videos uploaded through `videos.insert` by unverified API projects created after July 28, 2020 can be restricted to private viewing until the project passes Google's audit. Plan the public-publishing step around that requirement.

## What is NOT automatic yet

The current implementation does not yet turn the system on for daily production. The next engineering phase is:

1. Story/idea generator.
2. Story memory + near-duplicate check.
3. Persistent production job queue.
4. Generate video through the existing AutoTube AI pipeline.
5. QA.
6. Generate thumbnail.
7. Upload/schedule.
8. Persist publication.
9. Collect Analytics.
10. Feed analytics into the next batch of ideas.

Do not enable daily publishing until the private E2E test succeeds.
